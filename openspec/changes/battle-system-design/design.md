## Context

游戏是一款学园都市题材的策略经营游戏，基于《魔法禁书目录》IP。当前设计了丰富的超能力体系，但缺乏战斗系统。战斗仅在特定剧情节点触发（如大霸星祭、暗部冲突等），不是核心循环。

目标平台为微信小程序，技术栈为 Canvas 2D 像素风格。开发周期限制为 1-2 周 MVP。

## Goals / Non-Goals

**Goals:**
- 设计一个能体现不同能力系差异化的战斗系统
- 战斗系统有策略深度（配队、连招、反制）
- 操作简单（玩家只管放大招），但观赏性强（自动连招链）
- 适合像素风格的演出方式
- 适合小程序平台（轻量、碎片化）

**Non-Goals:**
- 不做成动作游戏（不需要实时操作）
- 不做复杂的装备系统
- 不做多人对战
- MVP 阶段不做前后台角色切换

## Decisions

### 1. 采用回合制 + 插队机制

**决策**: 使用行动条驱动的回合制，支持大招和自动小技能插队。

**理由**:
- 回合制适合小程序的碎片化场景（可以暂停）
- 插队机制增加策略深度（选择打断时机）
- 比纯自动战斗更有参与感
- 比即时制更容易做演出

**替代方案**:
- 即时自动战斗（冒险村物语式）：操作感弱，无法体现技能选择
- 纯回合制（无插队）：节奏太慢，缺乏打断博弈

### 2. 大招手动 + 小技能自动

**决策**: 玩家只负责点击释放大招，小技能由系统根据 Debuff 状态自动触发。

**理由**:
- 操作简单，符合小程序用户习惯
- 连招链自动触发，观赏性强
- 玩家决策点清晰：什么时候放大招

**替代方案**:
- 全自动：玩家参与感太低
- 全手动：操作太复杂

### 3. Debuff 叠层 + 反应系统

**决策**: 使用 Debuff 叠层机制，达到阈值触发效果；不同能力系组合触发反应。

**理由**:
- 体现不同能力系的差异化
- 为连招链提供触发条件
- 增加配队策略深度

**Debuff 体系**:
- 电磁系 → 带电（叠层触发眩晕）
- 流体系 → 潮湿（叠层触发减速，遇电触发感电扩散）
- 热能系 → 灼烧（持续伤害，遇潮湿触发蒸发）
- 心理系 → 干扰（属性减益，遇电触发混乱）
- 矢量系 → 偏转（反弹伤害）
- 空间系 → 扰乱（打断/位移）

### 4. 充能系统设计

**决策**: 大招需要充能才能释放，大部分角色使用普通充能（攻击/被攻击），个别强力角色使用特殊充能。

**特殊充能类型**:
- 连击充能：队伍累计攻击次数达标时充满
- 受击充能：队伍累计损失生命达标时充满
- 治疗充能：队伍累计回复生命达标时充满

**理由**:
- 控制大招释放频率，避免无限放大招
- 特殊充能增加角色差异化
- 充能条件与角色定位匹配

### 5. 4 人配队

**决策**: 每场战斗可上场 4 个角色。

**理由**:
- 足够展示连招链（2-3 人连招）
- 不至于太复杂（小程序操作）
- 后续可扩展前后台切换

## Risks / Trade-offs

| 风险 | 影响 | 缓解措施 |
|-----|------|---------|
| 像素风格演出效果有限 | 战斗观赏性不足 | 使用镜头语言（拉近、震动、停顿）弥补 |
| 连招链触发逻辑复杂 | 开发周期可能超预期 | MVP 阶段先实现 2-3 个简单连招链 |
| Debuff 系统数值平衡困难 | 战斗体验不稳定 | 先用简单数值，后续迭代调整 |
| 行动条插队逻辑复杂 | 可能出现 bug | 严格定义插队优先级，充分测试 |

## Open Questions

- 敌方 AI 的行为逻辑（是否也需要连招链）
